# Субагентный пайплайн новостного сайта

Этот скилл описывает полный процесс выпуска новости для статического блога.

## Главный принцип

Каждый этап выполняет отдельный субагент. Главный агент координирует, проверяет результаты, сохраняет файлы, включает публикацию и делает финальную браузерную проверку.

## Этапы

### 1. Исследование

Субагент: `research-agent`.

Скилл: `ai-topic-research`.

Задача:

- собрать источники;
- исключить маркетинговые материалы;
- подготовить отчет в `research/`;
- вернуть факт-лист: главный факт, контекст, ограничения, что нельзя утверждать.

### 2. Черновик новости

Субагент: `writing-agent`.

Скилл: `text-writing-pipeline`.

Задача:

- написать черновик новости для нетехнической аудитории;
- поставить дату в начале;
- использовать структуру: заголовок, лид, `Что случилось`, `Контекст`, `Ограничения`, `Что это значит для читателя`;
- не добавлять факты вне факт-листа.

### 3. Редактура

Субагент: `editor-agent`.

Скилл: `text-neurostyle-editor`.

Задача:

- убрать нейрояз;
- убрать канцелярит и пафос;
- заменить лишние английские термины русскими альтернативами;
- вернуть только отредактированный текст.

### 4. HTML-верстка новости

Субагент: `layout-agent`.

Скилл: `news-html-layout`.

Задача:

- сверстать новость отдельной HTML-страницей;
- использовать Tailwind CDN;
- добавить SEO, Open Graph, Twitter tags и JSON-LD;
- сохранить страницу в `news/<slug>-YYYY-MM-DD.html`.

### 5. Главная страница

Субагент: `homepage-agent`.

Скилл: `news-html-layout`.

Задача:

- обновить `index.html`;
- добавить карточку новости;
- проверить ссылку на HTML-страницу;
- сохранить общую SEO-разметку главной.

### 6. Публикация

Субагент: `publish-agent`.

Скилл: `gh-cli-ops`, если нужен GitHub CLI.

Задача:

- подготовить коммит;
- запушить в `main`;
- включить или проверить GitHub Pages;
- вернуть URL опубликованного сайта.

### 7. Браузерная проверка

Субагент: `browser-qa-agent` или главный агент, если браузер доступен только в основном потоке.

Скилл: browser/in-app browser workflow.

Задача:

- открыть главную страницу;
- открыть каждую HTML-страницу новости;
- проверить, что нет пустой страницы;
- проверить, что карточки ведут на нужные новости;
- проверить мобильный и десктопный размер, если возможно.

## Правила координации

- Субагенты не должны дублировать работу друг друга.
- Каждый субагент получает только свой вход и свой ожидаемый выход.
- Главный агент не принимает черновик как финал без редакторского этапа.
- Главный агент не считает работу завершенной без браузерной проверки всех текущих новостей.
- Если GitHub Pages еще не включен, главный агент включает Pages из ветки `main` и папки `/`.

## Финальные артефакты

В конце должны быть:

- отчет в `research/`, если выпуск начался с исследования;
- финальный текст в `posts/`;
- HTML-страница новости в `news/`;
- обновленная главная `index.html`;
- `sitemap.xml`;
- `robots.txt`;
- публичный GitHub Pages URL;
- подтверждение браузерной проверки всех страниц.
